# llm-rotator

Ротация API-ключей, моделей и прокси для OpenAI-совместимых LLM-провайдеров.

Библиотека берёт на себя рутину «попробовать ещё раз, но по-другому», когда
провайдер отвечает `401`, `429`, `403` из-за Cloudflare, `502/503/504` или
таймаутом. Она разбирается, **что именно сломалось** — ключ, адрес или модель, —
и решает, куда идти дальше: на следующий ключ, на следующий адрес того же ключа
или на следующего провайдера. Ключ никогда не ходит через чужой адрес.

Пакет не знает про конкретный проект: конфигурацию ему указывают явно
(`load_registry(base_dir=...)`), а историю диалога, личность и промпты он не
трогает.

## Установка

```bash
pip install "llm-rotator @ git+https://github.com/L-I-R-I-X/llm-rotator@v0.3.0"
# extras: [web] — DeepSeek Web (wasmtime), [server] — HTTP-сервис,
#         [auth] — вход в аккаунты (websockets)
pip install "llm-rotator[web,server,auth] @ git+https://github.com/L-I-R-I-X/llm-rotator@v0.3.0"
```

## Быстрый старт

```python
from llm_rotator import ModelRunner, load_registry

registry = load_registry(base_dir="/path/to/project")  # там models/ и .env
with ModelRunner(registry) as runner:
    response = runner.complete(
        "llama-3.3-70b-versatile",
        [{"role": "user", "content": "Привет"}],
    )
    print(response.text, response.origin)
```

`runner.complete()` перебирает **провайдеров, ключи и адреса одной модели**.
Выбор между моделями (цепочки ролей, привязка диалога) — задача вызывающего кода:
он зовёт `runner.send(...)` на каждую модель цепочки и решает, когда остановиться.

## Конфигурация

Каталог (`base_dir`) содержит подпапку `models/` и файл `.env`:

| файл | за что отвечает |
|---|---|
| `models/providers.toml` | адрес, стиль API, `auth`, `extra_headers` |
| `models/proxies.toml` | адреса выхода; `rotates = true` разрешает шарить |
| `models/keys.toml` | имя переменной из `.env` + провайдер + его прокси |
| `models/models.toml` | модель, провайдеры (порядок фейловера), окно, `max_output_tokens` |
| `models/chains.toml` | порядок моделей целиком (для надстройки ролями) |
| `models/clients.toml` | клиенты сервиса: токен → пространство имён (только `serve`) |
| `.env` | значения ключей, роли (`*_MODELCHAIN`), пределы хода |

Значения ключей лежат **только** в `.env`; в TOML хранится имя переменной.
Готовые примеры — в [`examples/`](examples/).

Валидация ссылочной целостности выполняется на загрузке и падает сразу, до
первого сетевого запроса, с перечислением допустимых имён. Ошибки —
`ConfigError`.

## Что считается сломанным

| ответ провайдера | кто виноват | куда дальше |
|---|---|---|
| 401 / 402 / 403 с ошибкой про ключ | ключ | следующий ключ |
| 403 без структурированной ошибки (Cloudflare/WAF) | адрес для этого провайдера | следующий адрес |
| отказ «по сети/региону» (`check your network settings`, `location is not supported`, `unsupported_country`…), любой код | адрес для этого провайдера | следующий адрес |
| 502/503/504/522 | адрес для этого провайдера | следующий адрес тем же ключом |
| таймаут, обрыв, отказ в соединении | адрес (для всех провайдеров) | следующий адрес тем же ключом |
| 404 со структурированной ошибкой | у провайдера нет модели | следующий провайдер |
| 429 / 403 про квоту | живой ключ, пауза (уважая `Retry-After`) | следующий ключ |
| 429 «request too large / reduce max_tokens» | велик потолок ответа | следующий провайдер |
| прочие 5xx | модель недоступна | следующий провайдер |
| 400 / 422 | запрос неверен | наружу, перебор бессмыслен |

«Адрес для провайдера» и «адрес вообще» — разные вещи: прокси, который не
пускает Groq, может работать с OpenRouter. Обрыв через `direct` считается
недоступностью провайдера, а не прямого соединения.

### Паузы вместо банов

Виноватый ключ, адрес или пара «адрес–провайдер» не выбывает до конца сессии,
а уходит на паузу. Каждый отказ подряд удваивает паузу (2 мин → 4 → 8 → …) до
потолка, первый же успех сбрасывает её: следующая снова начнётся с минимальной.
У процесса, который живёт неделями, бан «до конца сессии» значил бы «навсегда».
Связки, у которых пауза кончилась, но удачи ещё не было, пробуются последними —
после надёжных, чтобы запрос не ждал таймаута мёртвого адреса.

Пауза задаётся в `.env`:

```
LLM_BACKOFF_BASE = 120    # первая пауза, секунды (по умолчанию 120)
LLM_BACKOFF_MAX = 3600    # потолок паузы, секунды (по умолчанию 3600)
```

## Веб-чаты (аккаунты вместо ключей)

Кроме API-ключей ротатор умеет работать через **веб-чаты под аккаунтом**. Пока
это DeepSeek Web (`api_style = "deepseek_web"`, `auth = "web_session"`); каждый
сайт — отдельный транспорт.

```toml
# providers.toml
[providers.deepseek_web]
provider_name = "deepseek_web"
api_style = "deepseek_web"
base_url = "https://chat.deepseek.com"
models_url = ""
auth = "web_session"
[providers.deepseek_web.web.models]
"deepseek-web" = { thinking = false, search = false }

# keys.toml — вместо имени переменной из .env файл сессии
[[keys]]
key_name = "DS_ONE"
provider = "deepseek_web"
key_file = "accounts/one.json"
proxies = ["direct"]      # прокси закрепляется правкой этой строки
```

Полный список настроек (`inline_max_chars`, `first_event_timeout`,
`chat_max_turns`, `delete_policy`, `images`, …) — в
[`examples/models/providers.toml`](examples/models/providers.toml).

Что делает веб-слой:

* **Изоляция разговоров.** Запрос несёт `ConversationHint(namespace, session)`;
  разговоры из разных пространств имён никогда не делят удалённый чат.
  Дельта уходит в существующий чат, только если **доказано** продолжение
  (ключи сообщений — строгий префикс запроса); иначе новый чат с полным
  контекстом. `runner.complete(..., conversation=ConversationHint("hermes", "s1"))`.
* **Уборка.** Ротатор удаляет свои брошенные и простаивающие чаты через ту же
  связку (фоновый поток, очередь в SQLite `state/rotator.db`). Чужие чаты не
  трогает. `delete_policy`: `abandoned` | `after_turn` | `never`.
* **Быстрый уход с недоступного аккаунта.** Таймаут до первого события,
  отказы внутри HTTP 200 (`INVALID_TOKEN`, `backend_busy`, лимиты) —
  в нормальные `Failure`; порядок связок: где идёт разговор, затем самые
  давно простаивавшие, затем занятые (`max_concurrent`).
* **Большой контекст** уходит файлом (`context.md` и вложения), по `(аккаунт,
  sha256)` грузится один раз; картинки — при `images = true`.
* **tool calling** эмулируется промптом и терпимым разбором ответа.

Файлы, загруженные в аккаунт, ротатор удалить не может (у сайта не нашлось
доступного эндпоинта); чаты — может.

## Вход в аккаунты и диагностика

```bash
llm-rotator auth deepseek                # цикл входов в новые аккаунты
llm-rotator auth deepseek work@mail.com  # новый аккаунт с заданным именем
llm-rotator auth deepseek DS_ONE         # перелогин аккаунта, уже описанного в keys.toml
llm-rotator accounts sync                # завести ключи для файлов из accounts/
llm-rotator doctor                       # прокси, токены, ключи; только чтение
```

* **Без имени** открывается браузер, вы входите в аккаунт и жмёте Enter в
  терминале. Только после удачного входа спросят имя (Enter — свободное
  `DS_n`), потом: Enter — войти в ещё один аккаунт, Ctrl+C — закончить.
  Удобно, чтобы завести много аккаунтов подряд. Каждый круг идёт с чистым
  профилем браузера, поэтому прошлый аккаунт не подхватывается.
* **С именем**, которого нет в keys.toml, создаются `accounts/<имя>.json`
  (права 600) и блок `[[keys]]` (прокси `direct`, `max_concurrent = 1`). Имя
  может быть почтой. Имя из keys.toml — это перелогин: файл и прокси берутся
  из ключа, профиль браузера `state/chrome/<имя>` сохраняется.
* **Блоки руками писать не обязательно.** `accounts sync` добавляет ключи для
  файлов из `accounts/`, которых нет в keys.toml (`--dry-run` — только показать).
  Убрать аккаунт — удалить его блок. Файл сессии остаётся, и следующий `sync`
  заведёт его снова; не нужен — удалите и файл. `serve` предупреждает о таких
  файлах при старте.
* После `auth` и `sync` сервис нужно перезапустить, чтобы он увидел новые ключи.

Прокси с логином и паролем Chrome во флаге не принимает — будет понятная
ошибка. `doctor` помечает мёртвые аккаунты `needs_auth` и подсказывает команду
перелогина.

## Сервис (OpenAI-совместимый HTTP)

```bash
llm-rotator serve --base-dir /path/to/project [--host 127.0.0.1] [--port 9660]
```

| эндпоинт | |
|---|---|
| `POST /v1/chat/completions` | stream и обычный, `tools`; `model` — модель или `chain:<имя>` |
| `GET /v1/models` | модели и цепочки (`chain:*`) |
| `GET /status` | паузы, занятость, здоровье веб-аккаунтов, очередь чатов (без ключей и путей) |
| `GET /health` | жив ли процесс |
| `POST /admin/reload` | перечитать конфигурацию (loopback или `LLM_ROTATOR_ADMIN_TOKEN`) |

Клиенты (`models/clients.toml`): каждому харнессу свой токен
(`Authorization: Bearer …` или `x-api-key`) → своё пространство имён → свои
удалённые чаты. Внутри клиента разговоры разводят `X-Session-Id` или поле
`user`. Без `clients.toml` работает один клиент без токена, только с loopback.

В ответе — заголовки `X-Rotator-Origin` (`модель | провайдер | ключ | прокси`) и
`X-Rotator-Attempts`. Ошибки: `429` + `Retry-After`, если всё на паузе по
квоте; `503` со сводкой по цепочке; `400` на плохой запрос. Паузы переживают
перезапуск. Anthropic `/v1/messages` пока нет.

Пример юнита systemd — [`deploy/llm-rotator.service`](deploy/llm-rotator.service).

## Опрос каталога моделей

```bash
llm-rotator-discover --poll     # опросить провайдеров
llm-rotator-discover --merge    # дописать найденное в models/models.toml
```

Запускать из каталога с `models/` и `.env`.

## Устройство

* `registry` — TOML/.env, валидация, `Registry` и связки (`Binding`, `Route`).
* `gateway` — правила отказа, `SessionState`, `TurnBudget`.
* `transport` — одна попытка на связке (OpenAI-совместимый слой).
* `runner` — `ModelRunner`: вызов одной модели с обходом.
* `discovery` — список моделей у провайдеров.
* `web/` — веб-чаты: клиент и транспорт DeepSeek, планировщик хода, хранилище
  (SQLite), уборщик чатов, эмуляция tools, вход через Chrome.
* `service/` — HTTP-сервис: приложение, клиенты, цепочки, формат OpenAI.
* `cli`, `doctor` — `llm-rotator serve | auth | doctor`.

## Разработка

```bash
pip install -e ".[dev,web,server,auth]"
ruff check .
ruff format --check .
python -m unittest discover -s tests -t .
```

Живые тесты против настоящих аккаунтов (`tests/live/`) не запускаются сами:
`LLM_ROTATOR_LIVE=1 LLM_ROTATOR_LIVE_ACCOUNTS=a.json,b.json python -m unittest
tests.live.test_deepseek_live`. Они создают чаты только через ротатор и в
конце удаляют их. PoW сверяется с эталоном при `LLM_ROTATOR_POW_WASM=<путь к
sha3_wasm_bg.*.wasm>`.
